## Design Context

### Users

VibORM's documentation serves adopting TypeScript developers first. They may
already know another ORM, especially Prisma, and need to move from evaluation
to a correct working integration without reconstructing the library's internal
architecture. Contributors and evaluators remain secondary audiences.

The primary job is to build correctly: choose a compatible database driver,
define a schema, initialize a client, manage the database, and use the query API
with a clear understanding of current alpha limitations.

### Brand Personality

Precise, calm, and candid. The documentation should feel technically rigorous
without becoming academic, and should state incomplete or unstable behavior
directly rather than hiding it behind promotional language.

### Aesthetic Direction

A restrained, documentation-first interface with strong information hierarchy,
high legibility, and minimal decoration. Both light and dark themes should
support long technical reading sessions. Visual emphasis should communicate
navigation, warnings, code, and task progression rather than decorate them.

### Design Principles

1. Organize the primary navigation around adoption tasks before implementation layers.
2. Put runnable, production-shaped examples close to the decisions they explain.
3. Reveal internals and exhaustive reference material after the common path is clear.
4. Keep terminology consistent across guides, driver pages, migration pages, and API reference.
5. Surface alpha limitations at the point where they affect a reader's decision or code.
