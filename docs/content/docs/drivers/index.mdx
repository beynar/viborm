VibORM supports multiple database drivers across three dialects: PostgreSQL, MySQL, and SQLite.

## PostgreSQL Drivers

| Driver | Package | Best For |
|--------|---------|----------|
| [pg](/docs/drivers/postgresql/pg) | `pg` | Traditional Node.js apps with connection pooling |
| [postgres](/docs/drivers/postgresql/postgres) | `postgres` | Modern apps using postgres.js |
| [pglite](/docs/drivers/postgresql/pglite) | `@electric-sql/pglite` | Local/embedded PostgreSQL (WASM) |
| [neon-http](/docs/drivers/postgresql/neon-http) | `@neondatabase/serverless` | Serverless/edge deployments |
| [bun-sql](/docs/drivers/postgresql/bun-sql) | `bun:sql` | Bun runtime applications |

## MySQL Drivers

| Driver | Package | Best For |
|--------|---------|----------|
| [mysql2](/docs/drivers/mysql/mysql2) | `mysql2` | Traditional Node.js MySQL apps |
| [planetscale](/docs/drivers/mysql/planetscale) | `@planetscale/database` | PlanetScale serverless MySQL |

## SQLite Drivers

| Driver | Package | Best For |
|--------|---------|----------|
| [sqlite3](/docs/drivers/sqlite/sqlite3) | `better-sqlite3` | Node.js apps with local SQLite |
| [libsql](/docs/drivers/sqlite/libsql) | `@libsql/client` | Turso cloud or local libSQL |
| [bun-sqlite](/docs/drivers/sqlite/bun-sqlite) | `bun:sqlite` | Bun runtime with SQLite |
| [d1](/docs/drivers/sqlite/d1) | Cloudflare Workers | Cloudflare D1 in Workers |

## Feature Matrix

| Driver | Dynamic Transactions | Batch Mode | Migration Atomicity | Environment |
|--------|---------------------|------------|---------------------|-------------|
| pg | ✅ Full | ✅ Full | ✅ Full | Node.js |
| postgres | ✅ Full | ✅ Full | ✅ Full | Node.js |
| pglite | ✅ Full | ✅ Full | ✅ Full | Any (WASM) |
| neon-http | ❌ Unsupported | ✅ Full | ⚠️ Push only; `migrate apply` rejects | Any |
| bun-sql | ✅ Full | ✅ Full | ✅ Full | Bun |
| mysql2 | ✅ Full | ✅ Full | ⚠️ DDL-limited | Node.js |
| planetscale | ✅ Single-shard atomic | ✅ Single-shard atomic | ⚠️ DDL-limited | Any |
| sqlite3 | ✅ Full | ✅ Full | ✅ Full | Node.js |
| libsql | ✅ Full | ✅ Full | ✅ Full | Any |
| bun-sqlite | ✅ Full | ✅ Full | ✅ Full | Bun |
| d1 | ❌ Unsupported | ✅ Full | ⚠️ Push only; `migrate apply` rejects | Workers |

:::info
**Dynamic Transactions** use the callback API: `$transaction(async (tx) => { ... })`

**Batch Mode** uses the array API: `$transaction([op1, op2, ...])`

Drivers marked "Unsupported" reject instead of running non-atomically. See
[Transactions](/docs/client/transactions) for the client API and
[Migrations](/docs/migration#atomicity) for what migration atomicity means
per driver.
:::

## Closing the Connection

`await client.$disconnect()` closes the client's driver. Where the platform has
the explicit-resource-management protocol, `await using` does the same thing at
the end of the block — including when the block is left by a throw:

```ts
await using client = createClient({ driver, schema });

const users = await client.user.findMany();
// leaving this block closes `driver`, thrown or not
```

Disposal and `$disconnect()` are the same close path, so combining them in
either order closes once and throws nothing. Drivers are disposable too
(`await using driver = new PgDriver({ ... })`).

The interactive transaction client is deliberately **not** disposable: inside
`$transaction(async (tx) => ...)`, the transaction owns its driver's lifetime,
and a `using` block that tried to close it would be fighting the transaction.

:::info
**Type requirements.** Nothing here raises the compiler floor for code that
never writes `await using`: viborm's disposal member is declared so that it
degrades to nothing when `Symbol.asyncDispose` is not declared in your
`lib`/`@types`. The measured floor for consuming the package is `lib: ["es2022"]`
with `skipLibCheck` on and no `@types/node` required — the same floor as before
`await using` existed, verified by `pnpm test:package:consumer-floor`.

To *use* `await using` you need `Symbol.asyncDispose` declared — either a `lib`
including `esnext.disposable` (TypeScript ≥5.2) or `@types/node` ≥20, which
polyfills it — and a runtime that has the symbol (Node ≥18.18).
:::

## Choosing a Driver

- **Node.js traditional**: Use `pg`, `mysql2`, or `sqlite3`
- **Serverless/Edge**: Use `neon-http`, `planetscale`, `libsql`, or `d1`
- **Bun runtime**: Use `bun-sql` or `bun-sqlite`
- **Cloudflare D1**: Use `d1` with a Workers binding; its `batch()` primitive is the supported atomic path
- **Local development**: Use `pglite`, `sqlite3`, or `bun-sqlite`
