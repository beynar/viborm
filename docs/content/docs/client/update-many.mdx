---
title: updateMany
description: Update every record matching a filter
icon: PencilLine
---

Update every record matching the filter, in one call:

```ts
const result = await client.user.updateMany({
  where: { role: "GUEST" },
  data: { role: "USER" },
});
// Result: { count: 42 }
```

`updateMany` returns a `{ count }`. `where` is optional — omit it to update every row.

## Examples

```ts
// Archive old drafts
await client.post.updateMany({
  where: {
    createdAt: { lt: new Date("2023-01-01") },
    published: false,
  },
  data: { archived: true },
});

// Apply a discount with an atomic update
await client.product.updateMany({
  where: { category: "electronics" },
  data: {
    price: { multiply: 0.9 }, // 10% off
  },
});
```

## Getting the rows back

Add a `select` and `updateMany` returns the updated rows instead of a count. The
return type follows: with `select` it is an array of the projected rows, without
it, `{ count }`.

```ts
const updated = await client.post.updateMany({
  where: { published: false },
  data: { published: true },
  select: { id: true, title: true },
});
// Type: { id: string; title: string }[]
```

The rows are read **after** the update, so an atomic operation on the primary key
returns the new identity, not the old one.

<Callout type="info">
  There is no separate `updateManyAndReturn` method (Prisma has one). Passing
  `select` **is** the returning form. That `select` takes **scalar fields only**:
  a relation key inside it, `_count`, and `include` are all refused with a typed
  error before the update runs. Read relations in a follow-up query. (Prisma
  divergence, deliberate: Prisma's `updateManyAndReturn` does accept relations
  there.)
</Callout>

## Options

```ts
await client.user.updateMany({
  where: { ... },       // Optional: filter (all rows if empty)
  data: { ... },        // Required: fields to update
  select: { ... },      // Optional (scalar fields only): return the updated rows
                        // instead of { count }
});
```
