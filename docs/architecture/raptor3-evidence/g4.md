### G4-01 — query and projection semantics

Required behavior: inventory rows OP-R01–R09, Q-W01–Q-W10, Q-O01–Q-O04,
Q-P01–Q-P03, Q-S01–Q-S03, Q-A01–Q-A02, Q-R01, plus the read/filter/projection
crossings of SC-01–SC-14 and SL-01–SL-10. Root `delete` (OP-W03) is deferred
to G4-02 because it is a write lowering, not a read owner.

Current owner: `Queries` in `shared/query.ts`. Selectors: `prepareWhere`,
`prepareScalarOperations` (equals/in/gt/gte/lt/lte/not only), relation
quantifiers some/none/every/is/isNot. Ordering: `order`/`orderTerms` (scalar
asc/desc only). Paging: `select` (take/skip only). Projection: `prepareProjection`
/ `lowerProjection` / `decodeValue` (scalars limited to int, string, float,
decimal; relation carriers; variant arms). Grouping: `grouped` with its own
field/shape assembly and `lowerValuePredicate` for `having`. Admission:
`EngineSchema.admit` consumes the existing registry operation schemas;
`commands/index.ts` gates verbs.

Smallest proposed change: extend the one prepared-predicate vocabulary with
the remaining admitted operators (string modes, `notIn`, list containment,
JSON path/sentinel predicates, GeoPoint tiers, to-one shorthand, tagged
variants); extend order terms (`{ sort, nulls }`, to-one relation paths,
collection `_count`, distance); add cursor/distinct to the same page owner at
root and per-parent correlation; express `count`, `aggregate`, `exist`,
`findFirst` and the `OrThrow` forms as cardinality/shape decisions over the
same select/projection owner; decode every scalar through the existing codec
owners rather than per-type ladders.

Expected deletions inside the candidate: the duplicated operator ladder in
`lowerValuePredicate` (having) versus `prepareScalarOperations` collapses into
one operator vocabulary applied to any expression; `grouped()`'s separate
field/shape assembly folds into `prepareProjection`'s shape ownership; the
`findUnique` `take: 1` special case in the entry becomes the cardinality owner's
decision. Invariant: one prepared predicate and one prepared projection per
admission scope; SQL and dependency facts consume the same predicate.

one region for a multi-statement borrowed operation when that grant is
