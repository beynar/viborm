# Raptor 3 — remaining shipped-feature inventory

Date: 2026-09-09. Status: **frozen G3P-01 input; not a G3-prep or G3
pass**.

This inventory is the replacement candidate's remaining behavior ledger after
the accepted G2.7 source. It is derived from the shipped client surface,
operation schemas, scalar and relation validation, and registered contract
suites. It is not the earlier informal list of 22 features. Each row has a
stable inventory ID and names one distinguishable public behavior or refusal.
The C01–C13 families remain useful cross-cutting labels, but no family row is
treated as a completed cell.

## Reading the inventory

Candidate status means the private structured-command engine at the qualified
G2.7 boundary:

- **proven** — a registered Raptor 3 candidate cell already executes the
  behavior in its stated slice;
- **partial** — some placements or operators execute, but this inventory names
  remaining breadth or composition;
- **absent** — the candidate entry does not admit the public operation or this
  behavior yet;
- **refused** — the shipped contract deliberately rejects the shape; the
  candidate must preserve that refusal if the public route reaches it;
- **external** — the shipped owner remains outside the private engine. G3 may
  compose against it, but cannot duplicate it. Public integration remains G4.

Provider/profile codes are applicability, not claims that every cited suite
runs every driver:

| Code | Meaning |
|---|---|
| V | Provider-independent validation, type, construction, or deterministic SQL contract |
| SI / SB | Real SQLite interactive / restricted atomic-batch profiles in the Raptor harness |
| PGL | Real PGlite PostgreSQL execution |
| PG / MY | Native PostgreSQL / MySQL execution where provider behavior is material; exact server versions belong to each run's receipt |
| TW / TA | Scripted weak-returning / acknowledged-returning transport profiles |
| ALL | All applicable shipped PostgreSQL, MySQL, and SQLite driver families; G4 must preserve the current support matrix |

“G3P seed” means the prep unit may add the smallest real vertical slice needed
to prove ownership. It does not complete the inventory row. G3 completes C08–C11
on those accepted slices. G4 completes the full read, codec, lifecycle, public
type, and provider envelope.

## Completeness basis and exclusions

The public verb list is the 16-name `Operations` union in
[`src/client/types.ts`](../../../src/client/types.ts) and the same explicit list
in [`src/client/schema-introspection.ts`](../../../src/client/schema-introspection.ts).
The validation registry contributes 14 operation schemas in
[`src/validation/model/args/index.ts`](../../../src/validation/model/args/index.ts);
the two `OrThrow` verbs deliberately reuse the corresponding find schema. The
four raw methods come from [`src/client/raw.ts`](../../../src/client/raw.ts).
The relation and scalar rows come from every factory exported by
[`src/schema/index.ts`](../../../src/schema/index.ts), every scalar schema
dispatcher arm in
[`src/validation/scalars/index.ts`](../../../src/validation/scalars/index.ts),
and the ordinary and variant relation schema factories under
[`src/validation/relations/`](../../../src/validation/relations/index.ts).

The evidence census inspected all 556 files under `tests/contracts/`, the
literal query/write registrations in
[`scripts/query-engine-test-manifest.mjs`](../../../scripts/query-engine-test-manifest.mjs),
the client and driver manifest selectors, and the current Raptor registrations
in [`scripts/raptor3-manifest.mjs`](../../../scripts/raptor3-manifest.mjs) and
[`tests/raptor3/contracts.ts`](../../../tests/raptor3/contracts.ts). A cited
behavior module is authoritative even when provider wrappers register it in
several suites. The inventory links the smallest useful owners instead of
copying test bodies.

Schema definition, migrations, CLI, release, and cache-backend administration
are excluded unless the query/write engine consumes their facts. They remain
unchanged public boundaries, not feature savings. Native type catalogs are not
expanded into one row per SQL spelling: the distinguishing engine contract is
the logical scalar/list codec plus destination-aware lowering. Recursive reads
are included only as the approved private engine-fit witness; there is no public
`recurse` operation or argument to inventory. Internal
`createManyAndReturn`, `updateManyAndReturn`, and `deleteManyAndReturn` tokens
are result-routing discriminants, not public verbs.

The inventory does not authorize six parallel implementations. It fixes the
handoff order and the minimum slice each unit may use:

codecs, and representative native PostgreSQL/MySQL recursive lowering.
